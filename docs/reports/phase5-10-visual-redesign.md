# 视觉重设计：校勘本（critical edition）

老板授权的奖项级视觉改造。本文记录设计语言、可核验的量化指标与改动边界。

---

## 1. 设计概念

这个产品的承诺是「每条结论都能追到命盘要素与典籍底本」。视觉因此不选
SaaS 仪表盘那套卡片与阴影 —— 它会把「证据」讲成「指标」—— 而选**校勘本**：

| 元素 | 校勘本的对应物 |
|---|---|
| 左栏页边注 | 卷次索引（壹贰叁肆伍陆），滚动时粘性跟随 |
| 朱印 | 卷首右上角的「命理」小印，轻微旋转 |
| 栏线 | 章节之间的细横线，替掉卡片边框 |
| 条目编号 | 证据链每条左侧的 01/02/03，像校勘记的行号 |
| 脚注块 | 出处（URN + 底本 + 逐字原文 + 可打开地址） |
| 尺度尺 | 证据强度画成 0–1 的刻度尺，不是进度条 |

**为什么不是深色 + 霓虹 + 大字动效**：那套语言在讲「酷」，这套产品在讲
「可信」。奖项级不等于最炫，等于每个决定都能说出理由。

## 2. 字体与节奏

| 用途 | 字体 | 规格 |
|---|---|---|
| 标题 | 宋体（Songti SC / Noto Serif SC） | `clamp(40px, 6.4vw, 68px)`，字距 −0.015em |
| 中文副题 | 宋体 | 0.42em 大写字号，字距 0.34em |
| 正文 | 宋体 | 17px / 1.8，行宽 60–68 字 |
| 数据（URN、字段路径、算法版本） | 等宽（SF Mono） | 10–11.5px，字距 0.02–0.24em |
| 卷次/小标 | 等宽大写 | 10–11px，字距 0.2–0.3em |

**为什么数据用等宽**：URN 与 `chart.pillars[*].hidden_stems` 是标识符，
不是文句。字形本身就该区分开 —— 读者一眼知道「这串是可以去查的东西」。

## 3. 色彩（全部按 WCAG AA 验过）

| 变量 | 值 | 纸底对比度 | 用途 |
|---|---|---|---|
| `--ink` | `#191510` | 15.84 | 标题、正文 |
| `--ink-soft` | `#3d362b` | 10.40 | 次级正文、条件取值 |
| `--muted` | `#675e4e` | 5.57 | 说明文字、标签 |
| `--faint` | `#6f6656` | 4.94 | 最小号注文（仍 ≥ AA） |
| `--seal` | `#9b2c24` | 6.59 | 主按钮、卷次号、出处竖线 |
| `--ochre` | `#7d5a28` | 5.44 | 偏旺标记、卷首小标 |
| `--jade` | `#2c6650` | 5.86 | 审查通过 |

三种底色（纸 `#f4efe4`、卡片 `#fbf8f1`、脚注底 `#efe8da`）逐一验过，
最低值：muted 5.24、faint 4.64、ochre 4.96、seal 6.00 —— 全部 ≥ 4.5。
层级靠字号与字距拉开，不靠继续变浅：变浅的下一步就是不合格。

**唯一的实心红是主按钮**（多主题分析）。它必须比页面上任何东西都重 ——
用户来这里是做分析的，不是来读页脚的。

## 4. 动效与微交互

全部包在 `prefers-reduced-motion: no-preference` 里；减少动效时连 CSS
过渡都显式关掉（`transition: none`），不是只关一半。

| 动效 | 触发 | 时长/曲线 |
|---|---|---|
| 卷首上浮 | 载入，四段错峰 | 0.9s，cubic-bezier(.2,.7,.2,1) |
| 朱印落章 | 载入延迟 0.3s | 0.8s，缩放 + 旋转 |
| 章节进场 | IntersectionObserver | 0.7s，位移 10px |
| 强度尺填充 | 渲染后下一帧 | 1.1s |
| 强度数字滚动 | 渲染 | 0.9s，三次缓出 |
| 页签下划线 | 切换 | 0.25s |
| 按钮按下 | `:active` | 位移 1px |

微交互：请求期间按钮进入忙态（`aria-busy` + 文案「推演中…」）、URN
一键复制并回显「已复制」、出处链接下划线渐显、时间轴节点 hover 变朱色。

---

## 5. 响应式

| 断点 | 变化 |
|---|---|
| > 1024px | 左栏粘性页边注 + 884px 正文栏 |
| ≤ 1024px | 左栏折叠成横向索引，隐私三栏变单栏 |
| ≤ 720px | 单栏、输入撑满、触屏目标 44px、四柱表表内横向滚动 |

390×844 实测：页面级横向溢出 **0px**。

---

## 6. 改动边界（哪些没动）

- **零依赖单页**：没有构建链、没有框架、没有 web font 下载。
- **`textContent` 纪律**：全部文本走 `textContent`，`innerHTML` 零赋值。
- **数据路径**：契约测试的 `RESPONSE_CONTRACT` 一条未改 —— 只改呈现。
- **id 与文案**：E2E 依赖的 40 余个 id 与关键文案全部保留。

## 7. 验证

| 项 | 结果 |
|---|---|
| `pytest tests/ -q` | 1398 passed |
| 契约测试（前端读取路径） | 10 passed |
| E2E（真实浏览器） | 16 passed |
| 骨架快照 | 已重生成（`tests/snapshots/frontend_chrome.txt`） |
| ruff / mypy | 干净 / 0 错 |
| 390px 横向溢出 | 0px |

**设计期的自审循环**（对应任务书的 CHECK 列表）共四轮，修掉的问题：
`el()` 把类名当文本（census 行、gauge 刻度）、`<b>` 标签写进 textContent、
藏干因 `display:flex` 用在 `td` 上被压成竖排、五行条数字贴边被切、
条件键 `word-break: break-all` 导致单词中间断行、三档文字色对比度不足 AA。

## 8. 已知取舍

1. **不做插画与 3D**：这套设计的力量来自排印，不来自图像。加插画会稀释
   「这是一份文件」的暗示。
2. **不做滚动视差**：数据密集页面里，视差会让阅读位置漂移。
3. **深色模式未做**：纸色是这套语言的地基，深色需要另一套完整的墨色体系，
   不是反色能解决的。若要做，应当作为独立提案。
