# Phase 5.8 验收报告：隐私、删除与数据保留策略

子任务：Phase 5（完整产品体验）→ 5.8 隐私、删除与数据保留策略。
本报告按阶段统一执行流程的要求写。

**先给结论**：这套系统**不存用户数据**。没有数据库、没有账号体系、
没有历史记录、没有请求体日志。需要披露的只有两处内存态：规则库（静态
语料，与用户无关）与 provider 响应缓存（至多 256 条，进程退出即消失）。
所以「删除」这个动作在本系统里没有服务端对象可作用 —— 这不是回避，
是把事实说清楚。

## 2. 数据清单（逐项核实，不凭印象）

| # | 数据 | 位置 | 生命周期 | 是否含用户信息 |
|---|---|---|---|---|
| D1 | 生辰（年月日时分、经纬度、性别、时区） | 请求体 → 内存 | 单次请求内 | **是**（用户输入） |
| D2 | 命盘与证据链 | 内存（响应对象） | 单次请求内 | 派生自 D1 |
| D3 | provider 响应缓存 | 内存（`AnalystAgent._response_cache`） | 进程生命周期；至多 **256** 条，FIFO 淘汰 | 键是完整提示词（含证据链文本），值是该次模型原始输出 |
| D4 | 规则库与语料 | 内存（进程启动时加载） | 进程生命周期 | 否（公有领域典籍） |
| D5 | 导出文件（JSON/PDF） | 用户设备（浏览器下载） | 用户自己管理 | 是（报告内容） |
| D6 | HTTP 访问日志 | 由部署方的 uvicorn/反代决定 | 部署方决定 | 默认只含 method/path/status，**不含请求体** |

### 2.1 关于 D3 的准确说法

缓存键是 `(system_prompt, user_prompt)` 的完整文本。提示词由证据链
构建，**不含**原始生辰字段（年月日时分/经纬度/性别），但含命盘派生
信息（四柱、藏干十神、条件实际值）。因此：

- 它**不是**「原始生辰的副本」；
- 它**是**「由生辰派生的分析输入」，仍属用户相关数据；
- 上限 256 条、FIFO 淘汰、无落盘，进程重启即清空。

这条区分要写进文档而不是含糊过去：说「缓存里没有用户数据」是错的，
说「缓存里有完整生辰」也是错的。

### 2.2 关于 D6 的边界

本仓库的 `api.server` 用 uvicorn 默认访问日志，只记
`method path status`。**部署方若在反向代理层开启请求体日志，那不在
本项目控制内** —— 本项目的承诺到「自己这层不记录」为止，不替部署方
背书。这一点在页面隐私声明里也写明。

## 3. 删除与保留

| 诉求 | 实际处置 |
|---|---|
| 「删除我的数据」 | 无服务端记录可删。D1/D2 随请求结束即释放；D3 由进程重启清空 |
| 「不要保留我的分析」 | 不落盘，无需操作；如部署方自行加了日志，需在部署侧清理 |
| 「导出后删除」 | 导出文件在用户设备上，由用户自行删除；服务端无副本 |
| 保留期限 | 服务端无持久化数据，故无「保留期」概念；D3 是缓存不是存档 |

**为什么不做「删除接口」**：没有存储就没有删除。加一个 `DELETE /api/data`
只会制造「我们有你的数据」的错觉 —— 那比没有接口更误导。真正需要删除
接口的是有账号体系的系统，本系统不是。

---

## 4. 页面上的隐私声明

`static/index.html` 页脚新增隐私声明区，三条要点：

1. 不存储：无账号、无数据库、无历史记录；生辰只用于当次计算。
2. 内存缓存：最多 256 条结论缓存，进程退出即清空；缓存命中在响应里
   可见（`served_from_cache`）。
3. 导出与日志：导出文件留在你的设备上；访问日志只含方法与状态码，
   请求体不记录（部署方另加日志的除外）。

**为什么写在页面上而不是只写在文档里**：用户不会去读 `docs/`。隐私
声明的最低标准是「用的人看得见」。

---

## 5. 反漂移：文档里的数字必须与代码一致

「最多 256 条」这个数字来自 `agents/mingli.py` 的
`RESPONSE_CACHE_LIMIT`。文档与代码各写一遍，改一处忘另一处是这类
声明最常见的腐烂方式。因此：

- 测试从 `RESPONSE_CACHE_LIMIT` 读常量，断言文档与页面里出现的数字
  与它一致；
- 改缓存上限必须同步改文档与页面，否则测试红。

这条与 Phase 4.3 的「契约指纹」同源：可核验的数字必须能被机器对上。

## 7. 已知问题与未实现

1. **D6 的部署侧日志**不在本项目控制内，只能披露、不能承诺。
2. **缓存不提供手动清空接口**。理由是它没有对外语义（清了也会被下一次
   请求填回），且进程重启是最直接的清空方式。若将来做多租户，这条要
   重审 —— 那时缓存会成为跨用户的数据面。
3. 报告导出文件里的个人信息由用户自己保管；本项目不做水印或加密。
