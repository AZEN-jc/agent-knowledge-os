# 开发/CI 工具依赖。
#
# 为什么单独一个文件而不是并进 requirements.txt：这两个是**工具**，不是运行时
# 依赖 —— 生产部署装 requirements.txt 就够，不需要 ruff 与 mypy。
#
# 为什么用 `-r requirements.txt` 引用而不是重抄一遍：抄一遍就有两份清单，
# 改一处忘另一处是这类文件最常见的漂移方式（本轮审计已经因为这个把
# lunar_python 漏在 requirements.txt 外面过一次）。
#
# 版本与 pyproject.toml 里 [tool.ruff] / [tool.mypy] 的配置配套：
# 这两个工具此前**没有任何地方声明为依赖**，新克隆装完 requirements.txt 跑
# `ruff check .` 会 command not found，于是「ruff 干净」「mypy 有处置方案」
# 两条验收无法从仓库复现。这是审计报告 §5 的 R4。
-r requirements.txt

ruff==0.16.10
mypy==2.4.0

# `fastapi.testclient` 需要 httpx（starlette 1.9 起会提示改用 httpx2，但
# 回退到 httpx 仍受支持）。**这不是可选项**：tests/ 里有 4 个文件 import
# TestClient，缺它会在 collection 阶段直接报 4 个错误，整个测试套件跑不起来。
#
# 为什么之前没被发现：早期环境里 httpx 是被别的包顺带装进来的，于是
# 「新克隆能不能跑测试」这件事一直没人真正验过。Phase 3.1 重建隔离环境时
# 才暴露 —— 与审计报告 §5 的 R4（ruff/mypy 配了却没声明）是同一类缺陷：
# **依赖声明只写了「代码 import 的」，漏了「测试脚手架 import 的」。**
httpx==0.28.1

# Playwright（Phase 5.2 E2E）：真实 Chromium 跑前端主链路。装包之外还要
# `python -m playwright install chromium` 下载浏览器二进制 —— CI 里有
# 专门步骤做这件事。缺浏览器时 tests/test_e2e_frontend.py 整套 skip
# （环境事实），不缺而不跑才是缺陷。
#
# 注意它与 httpx 的同与不同：httpx 是**没有就跑不了测试**，playwright 是
# **没有就少一类测试**。前者漏声明会让整个套件 collection 失败，后者只会
# 让 E2E 静默 skip —— 所以这条依赖的缺失更隐蔽，写进清单 + CI 装浏览器
# 两步都要做，只做一步都会得到「以为 E2E 在跑其实没跑」。
playwright==1.64.1
